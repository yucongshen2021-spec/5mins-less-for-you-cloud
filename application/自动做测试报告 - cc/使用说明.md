# FASTIP 自动测试报告 — 使用说明

## 一、目录结构与各文件夹作用

| 路径 / 文件             | 作用                                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `app.py`            | Web 入口（Flask）：提供界面、接收参数、调用引擎生成报告。由 portal 反向代理暴露为 `http://localhost:5000/app/test_report/`（容器内端口 5002）。 |
| `src/make_report.py` | 报告引擎：执行 CE SSH 与本机命令、生成截图与 Word。                                                                                              |
| `src/requirements.txt` | Python 依赖列表（开发环境安装用）。                                                                                                       |
| `src/README.md`     | 面向开发者的补充说明（若有）。                                                                                                             |
| `script/`           | **Word 模板**等静态资源目录。其中应包含 `FASTIP-测试报告.docx`（报告模板）。引擎会从此目录读取模板。                                                              |
| `log/`              | **每次运行**生成的日志与产物：子目录名一般为「日期数字_CID」；内含 `config.json`（本次参数）、`state.json`（断点状态）、`raw/`（命令原始输出文本，与截图一一对应）、`screenshots/`（由上述真实输出渲染的终端风格图）、以及生成的 `FASTIP-测试报告_*.docx`。 |

说明：请保证 `app.py` 与 `script/`、`log/`、`src/` 的相对位置与上述一致，否则引擎可能找不到模板或写错日志路径。

---

## 二、在 CE 设备上只会执行什么（安全边界）

本应用在 CE 上**仅通过 SSH 执行经白名单校验的网络探测类命令**，不会对 CE 做配置下发、改表、进入可编辑配置视图等操作。

按界面所选 **产品类型** 不同，CE 侧实际下发的命令形态如下（均为固定格式，参数来自您填写的 IP 与间隔项）：

- **ER**  
  - 四条均为：`sudo ping -c 500 -i <-i> -s 64|1500 <主线或备线 IPv4>`  
- **USG（华为）**  
  - 四条均为：`ping -c 500 -s 64|1500 -m <-m> <主线或备线 IPv4>`

引擎在发送前会用正则**严格匹配**整条命令；任何不在白名单内的 CE 命令都会被拒绝执行。除上述以外的 CE 操作（如 `conf`、`sys`、改路由等）**不会**被程序调用。

## 三、如何调用本机执行 ping / traceroute

引擎在运行所在主机上通过系统自带的 `ping` 与 `traceroute`（Linux）/ `tracert`（Windows）执行本地探测，并按 UTF-8 解码输出。

当前允许的本机命令格式为（站点为 IPv4 或域名，由您在界面中填写）：

- **Ping**  
  Linux: `ping -c 100 -s 1200 <本地站点或加速站点>`  
  Windows: `ping -n 100 -l 1200 <本地站点或加速站点>`
- **Traceroute**  
  Linux: `traceroute -w 1 -n <同一站点>`  
  Windows: `tracert -w 1 -d <同一站点>`

- 标准输出按 UTF-8 解码后写入日志与用于生成截图；**同样受白名单约束**，不会执行任意 shell 命令。

## 四、关于报告中的截图（真实数据渲染）

插入 Word 的 `screenshots/*.png` **不是凭空编造的画面**，而是：

1. 先在 CE（SSH）或本机上**真实执行**白名单内的 `ping` / `traceroute`（或 CE 侧对应命令）；
2. 将命令返回的**原始标准输出**完整保存到同一次运行目录下的 `raw/*.txt`；
3. 再把这些**真实回显文本**按终端风格排版，渲染为 PNG 嵌入报告。

因此：**截图内容与 `raw` 目录中对应 `.txt` 文件中的文字一致**，来源于当次实测输出；程序不会在未执行命令的情况下伪造探测结果。  
（开发/冒烟时若使用 `--mock-network` 等模拟模式，则属于**明确的测试假数据**，与正常出报告流程不同。）

## 五、日常使用建议

1. 通过 portal 统一入口进入测试报告页面，在界面填写 CID、CE、IP、站点等后点击「开始生成报告」。
2. 模板更新时，替换 `script/FASTIP-测试报告.docx` 即可（勿改文件名，除非您同步修改源码中的模板名常量）。
3. 排查问题时，打开对应 `log/<日期>_<CID>/` 下的 `raw/*.txt` 查看原始回显，与 `screenshots/*.png` 对照。

如有新的 CE 命令需求，必须在源码中**同步修改白名单与界面说明**，避免产生未授权操作。
