#### 二、16 用户多用户并发测试

新增 `application/test/blackbox_8000/test_multiuser_concurrency.py`（20 个测试），覆盖：
- **登录系统**（5 测试）：16 用户登录 + session cookie 互不相同、会话路由隔离、错误密码拒绝、重复注册拒绝、访客自动 session
- **工作区隔离**（4 测试）：16 用户独立 `data/users/<uid>/` 目录、yucs 自定义模板不泄漏给普通用户、16 用户并发生成无 WAN IP 串号、访客用共享 fallback
- **并发安全**（5 测试）：16 用户同时生成不同场景全 200、同一场景同一参数输出完全一致（无 ns 串号）、混合负载 3 轮全成功、yucs 并发 save/reset 期间普通用户不受影响、高并发 64 请求零 5xx
- **权限控制**（6 测试）：非 yucs save/reset/preview/init-defaults 全部 403，yucs 全部 200

**关键坑 & 解决：**
1. **ns 污染**：`api_template_reset` 会把读到的模板写回 ns（`ns[slot] = tpl`），一旦被脏模板污染就无法通过 reset 清除。解决：fixture 用 SIGHUP 重启 gunicorn worker + 轮询确认所有 worker 已刷新（连续 20 次返回出厂模板）
2. **busybox 容器无 kill 命令**：用 `bash -c 'kill -HUP <pid>'` 而非独立 `kill`
3. **IP 子串匹配**：WAN IP 验证用 `10.99.{idx}.1`（带尾 .1）避免 `10.99.1` 匹配到 `10.99.10`
4. **空 network 参数**：`_inject_network_to_module` 对空值不覆盖（设计如此），并发测试用显式完整参数

**结果：** 78 blackbox + 18 smoke = 96 passed

#### 七、Git Push 网络问题解决

`github.com` 默认解析到 `20.205.243.166`，其 443 端口不通（ICMP 通但 TCP 443 超时）。SSH 22 端口通但无 SSH key。

**解决方案**：在 `/etc/hosts` 中将 `github.com` 指向 443 可达的 IP `140.82.112.3`，然后正常 `git push origin main`。

已记录到 `docs/AGENTS.md` 的「Git Push 网络问题」章节。
